## Vision

### 10x Check
지금의 Glim은 "앱을 구경하는 곳". 10x 버전은 "메이커가 매일 아침 여는 곳".
핵심 루프: 메이커 앱 등록 → 유저 Try+피드백 → 메이커가 신뢰 가능한 숫자를 대시보드에서 확인 → 재방문 + 친구 메이커 초대. 현재 이 루프의 모든 화살표가 끊겨 있음(지표 위조 가능, 알림 부재, 정적 대시보드, 검색 부재). 2026년 시장 합의: 만들기는 쉽고 발견되기가 문제 — 앱스토어 제출 84% YoY 증가, 바이브 코딩 시장 $4.7B. TikTok-style 바이브 앱 발견에 자리 잡은 직접 경쟁자 부재.

### Platonic Ideal
바이브 코더가 금요일 밤 앱을 올린다. 토요일 아침 "어젯밤 23명이 써봤고 7명이 저장했어요" 알림이 온다. 대시보드에서 시간대별 Try 전환 그래프를 보고, "지도가 느려요" 피드백을 읽고, 그 자리에서 고치고, 업데이트 포스트를 올린다. 팔로워 40명에게 새 포스트가 뜬다. 이것이 "앱의 성장 여정을 함께 트래킹하는 플랫폼"의 실체.

## Accepted Scope (added to this plan)

### Part 1 — 신뢰 기반 수리 (B 스코프)
- **좋아요 전환 (설계 문서 정책 그대로 적용):** 좋아요는 **포스트 단위 + 로그인 필수** (likes 스키마 이미 그렇게 설계됨, `UNIQUE(postId, userId)`). 피드 카드는 이미 포스트이므로 카드의 좋아요 = 해당 포스트 좋아요. 익명 탭 → 로그인 프롬프트 (저장과의 의도적 비대칭, 설계 문서 Premise 3). `POST /api/likes` 토글 (insert/delete + likeCount 재계산). **구현 형태 (eng review):** follows 패턴을 복붙하지 말고 공용 `toggleAndRecount()` 헬퍼로 추출 — likes/saves/follows 3개 라우트가 "존재확인→토글→COUNT 재계산→캐시 갱신" 동일 파이프라인 공유 (DRY). **원자성: Drizzle D1은 인터랙티브 트랜잭션 미지원 — 토글+재계산은 `db.batch([...])`로 묶을 것** (게이트 1의 동시성 보장). **익명 localStorage 좋아요는 폐기** — 로그인 유저는 서버 상태가 진실, 클라이언트는 페이지 로드 시 내 좋아요 상태를 fetch.
- **저장 전환:** `POST /api/saves` 토글 (익명 anonId 허용 — saves 스키마의 partial unique index 활용), saveCount 재계산. 익명 localStorage는 보조 캐시로만 유지하고 서버와 동기화.
- **초기 상태 하이드레이션:** getFeedPosts가 세션 userId/anonId 기준 LEFT JOIN으로 `likedByMe`/`savedByMe`/`followedByMe` 플래그를 FeedItem에 포함 (SSR 한 번, 추가 라운드트립·깜빡임 제로). Feed/상세/FollowAppButton 전부 이 플래그를 초기값으로 사용 — 컴포넌트 간 상태 불일치 해소.
- **백필 (1회):** 마이그레이션 0001 이후 쌓인 interactions의 like/save 행을 identity 단위 dedupe하여 likes/saves에 `INSERT OR IGNORE` 백필 (0001 백필 SQL 패턴 재사용). **주의: OR IGNORE는 FK 위반을 무시하지 못하므로** WHERE에 `AND EXISTS (SELECT 1 FROM posts WHERE posts.id = 'post-' || interactions.app_id)` 가드 필수 (대상 포스트 없는 like 행이 전체 백필을 abort시키는 것 방지). 직후 모든 캐시 카운터 재계산. 구 클라이언트의 localStorage 전용 상태는 익명 저장만 다음 방문 시 서버에 동기화, 익명 좋아요는 드랍 (0001과 동일 정책).
- **랭킹 조작 가드:** anonymousId를 body가 아닌 **서버가 읽는 HMAC 서명 쿠키**로 결정. 서명 키는 `BETTER_AUTH_SECRET`에서 **HKDF 파생** (`info="glim-anon-v1"` — 버전 라벨로 회전 스토리 분리, 별도 시크릿 신설 없음. auth 시크릿 회전 시 익명 쿠키가 무효화되지만 익명 identity는 저위험이라 수용, 라벨 v2로 점진 이행 가능). **첫 익명 쓰기 = 쿠키 발급 + 해당 이벤트 수락** (거부/재시도 강요 없음); 이후 서명 불일치/미서명 값은 거부. `track.ts`의 body anonymousId 전송과 `lib/anon.ts`의 localStorage 생성은 제거 (merge도 동일하게 쿠키 기준). rate limit은 **Workers Rate Limiting binding** (2025-09 GA — wrangler.toml `[[ratelimits]]` 표준 바인딩, 베타 시절 `unsafe.bindings` 표기 아님) 우선, 불가 시 D1 슬라이딩 카운터 폴백, **dev/로컬/프리뷰는 no-op 림리터** (binding 부재 시 통과 + 경고 로그) — **키는 `CF-Connecting-IP` 기본** (identity는 위조·회전 가능하므로 보조 키로만), 한도: IP당 분당 60회/쓰기 라우트. App Score 집계는 identity 단위 dedupe (COUNT(DISTINCT COALESCE(user_id, anonymous_id)) — merge가 interactions user_id를 재소유하므로 로그인 전후 이중 카운트 없음).
- BETTER_AUTH_SECRET fail-closed (프로덕션에서 누락 시 throw)
- **마이그레이션 복구 (순서 강제):** ① `wrangler d1 export` 원격 백업 → ② 원격 `d1_migrations`의 0003·0004 행 존재 확인, 누락분 INSERT → ③ `wrangler d1 migrations list --remote`로 pending 0 확인 → ④ **메타 스냅샷 catch-up:** `drizzle-kit generate` 실행 (DB가 아니라 schema.ts↔최신 스냅샷 diff이므로 0001–0004 DDL을 재생성하는 catch-up 마이그레이션이 나옴) → 생성된 SQL이 기적용 DDL과 일치하는지 육안 검증 → **SQL 본문을 비우고**(no-op) 로컬·원격 d1_migrations에 적용 완료로 기록, 스냅샷 JSON만 채택 → ⑤ **구조 diff 게이트 (Codex 지적 수용):** 원격 `SELECT sql FROM sqlite_master` 덤프 ↔ 로컬 D1 동일 쿼리 ↔ schema.ts 기대 구조를 비교해 3자 일치 확인 후에야 catch-up을 적용 완료로 기록 → ⑥ 이후부터 `db:generate`/`db:migrate:remote` 정상 사용
- **commentCount 재계산 전환:** 댓글 작성 경로의 blind `+1`을 `SELECT COUNT(*)` 재계산으로 교체 (Signal Authority 표의 의무 사항 — follows 패턴과 동일하게 자가 치유형으로)
- 알림 페이지 inArray WHERE 추가, 배지 `SELECT COUNT(*)` 사용, lastNotifCheckAt + follows×posts join 배지 구현 (설계 약속분)
- 피드: SQL 후보풀 LIMIT (최신순 ~200) 도입, cursor(팔로잉/카테고리) 페이지네이션. **추천 피드 v1은 후보풀+40장 단일 배치로 충분 — seed-window는 포스트 200개 돌파 시점에 구현** (설계 결정은 유지, 구현 시점만 보류 — TODOS 기록)

- FeedbackModal/CommentsSheet: `res.ok` 검사 + 인라인 에러 표시 + busy 가드 + `isComposing` IME 가드

## Eng Review 부록 — 구현 디테일 명세 (2026-06-13, Codex eng pass 22건 수용)

**토글/카운터**
1. 토글은 "현재 상태 SELECT 후 반전"이 아니라 **클라이언트가 intent를 보냄** (`{action:'add'|'remove'}`): add = `INSERT OR IGNORE`, remove = `DELETE` — 동시 요청에도 멱등. 응답은 재계산된 카운트+상태.
2. `toggleAndRecount()` 헬퍼는 최소 골격만 일반화 ("mutation 실행 → COUNT 재계산 → 캐시 UPDATE"를 `db.batch()`로) — identity 술어(likes=userId, saves=userId XOR anonId)와 대상 캐시 컬럼은 라우트별 파라미터.
3. identity dedupe는 네임스페이스 프리픽스 필수: `COALESCE('u:'||user_id, 'a:'||anonymous_id)` (문자열 충돌 방지).

**HMAC/rate limit**
4. HKDF 파생 키는 **isolate당 1회 캐시** (모듈 레벨 Promise), salt는 명시적 zero-length `Uint8Array`. 검증은 base64 문자열 비교가 아니라 `crypto.subtle.verify()` (상수시간).
5. ratelimits 바인딩 구체화: `wrangler.toml [[ratelimits]] name="RL_WRITE" simple={limit=60, period=60}`, 호출 `env.RL_WRITE.limit({key})`. **D1 폴백 폐기** — GA 바인딩을 전제로 하고, 프로덕션에서 바인딩 부재 시 에러 로그 + 요청 통과(fail-open이지만 시끄럽게; 배포 체크리스트에 바인딩 확인 추가). dev/프리뷰는 no-op.
6. `CF-Connecting-IP` 부재 시(로컬 등) 서명된 anonId 버킷으로 폴백 — 전역 단일 버킷 금지.
7. 프로덕션 판정은 `NODE_ENV`가 아니라 **wrangler.toml `[vars] ENVIRONMENT="production"`** 명시 변수 (auth fail-closed·rate limit 공용 술어).

**백필/마이그레이션**
8. 백필 SQL: likes는 `user_id IS NOT NULL` 명시 필터 (익명 드랍), saves는 anon 수용 (0001 선례와 일관). **preflight 카운트 로그**: 대상 identity 수 vs 삽입 행 수 + 제외 사유별 수 — 조용한 under-backfill 방지.
9. 마이그레이션 구조 diff 게이트는 컬럼만이 아니라 **인덱스·FK·CHECK까지** 비교 (`sqlite_master`의 index/table 행 전체).

**스키마**
10. `mediaType='text'` 추가 시: Drizzle TS enum 갱신 + DB CHECK 부재 확인 + **미디어 URL 존재를 가정하는 모든 코드 경로 점검** (AppCard, 썸네일, OG 메타). For You 피드 WHERE에 `mediaType != 'text'` 명시.
11. `app_daily_stats`: PK `(appId, date)`, date는 **UTC `YYYY-MM-DD` TEXT** (타임존 경계 이중카운트 방지), 갱신은 `REPLACE`가 아니라 **`INSERT ... ON CONFLICT(appId,date) DO UPDATE`** (REPLACE는 delete+insert라 후속 컬럼 추가 시 위험).
12. merge가 interactions를 재소유하면 영향 앱들의 `app_daily_stats` 행을 **첫 영향일부터 삭제** (다음 롤업이 재계산) — 과거일 불변 원칙의 명시적 예외.
13. App Score·트렌딩 집계는 interaction **type 허용목록 명시** (badge_view 등 신규 타입이 점수 오염 못 하게).

**테스트**
14. better-sqlite3 테스트는 D1 방언 차이(RETURNING, partial index, date 함수) 때문에 **스모크 등급** — 게이트 2의 rate limit 검증은 "수동 curl"로 명시 재분류 (플레인 vitest로 증명 불가), `@cloudflare/vitest-pool-workers`는 TODOS 유지.
15. vitest config가 산출물: 경로 알리아스(@/) + 서버 전용 모듈 처리 포함한 `vitest.config.ts` 명시 — "스크립트 추가"만으로는 안 돌아감.
